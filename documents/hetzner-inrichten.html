Deel A · stap 1 t/m 7

In de browser: Hetzner

Eerst regel je alles in de Hetzner Console: het account, de beveiliging, het project, de sleutel, de firewall en de server zelf. Dit deel kost ongeveer een uur, maar een groot deel daarvan is wachten op de verificatie.

Een Hetzner-account maken

Dit deed je zelf. Claude heeft deze schermen niet gezien. Hieronder staat daarom alleen wat er moet gebeuren, niet welke knoppen er precies staan.

  1. Ga naar hetzner.com en registreer een account. Wij gebruikten een eigen account van de docent. Een account van de school is beter voor de overdracht en de afspraken met bedrijven, maar het regelen duurt langer.
  2. Bevestig je e-mailadres.
  3. Vul je gegevens in, en een betaalmethode.

Goed om te weten

Een account van de school is later niet zomaar over te zetten. Dan heb je een nieuwe server nodig.

2

browser± 5 min

Tweestapsverificatie (2FA) aanzetten

Met 2FA kan niemand in je account, ook niet met je wachtwoord, zonder de code op je telefoon. Dit doe je helemaal zelf, want de QR-code is een geheim.

  1. Open console.hetzner.com. Bovenaan staat de melding 2FA is not enabled yet. Klik op Enable 2FA now.
  2. Scan de QR-code met een authenticator-app op je telefoon.
  3. Staat er een veld voor een code van zes cijfers, typ dan de code uit je app. Staat er een veld voor een naam, vul dan iets in als telefoon.
  4. Klik op de groene knop Add.
  5. Laat Hetzner herstelcodes zien, bewaar die dan buiten de laptop, bijvoorbeeld op papier of in je wachtwoordmanager. Zonder die codes kom je niet meer in je account als je telefoon kwijt is. Zet ze niet in een chat of in de repo.

Controle: ververs de pagina. De melding 2FA is not enabled yet is weg.

Het account laten verifiëren

Bij ons kon er eerst geen project gemaakt worden. Na een klik op New project meldde Hetzner Verification pending. Je account moet eerst gecontroleerd worden.

  1. Ga naar accounts.hetzner.com en log in.
  2. Klik op Verification en volg de stappen. Hetzner kiest hoe, bijvoorbeeld met een kleine betaling of een foto van je identiteitsbewijs.
  3. Wacht. Soms gaat het meteen, soms duurt het uren. Bij ons was het na ongeveer een half uur rond.

Dit doe je zelf, want het gaat om je persoonsgegevens. Na de verificatie maakte Hetzner zelf een leeg project Default. Dat mag blijven; het kost niets.

De SSH-sleutel toevoegen

Met een SSH-sleutel log je in zonder wachtwoord. Hetzner zet het openbare deel van de sleutel straks zelf op de server. Wij gebruikten een sleutel die al op de laptop stond: ~/.ssh/id_ed25519_adhibera.

1. Op de laptop: laat het openbare deel zien. Dat is het bestand dat eindigt op .pub. Dat mag je delen; het bestand zonder .pub is geheim.

cat ~/.ssh/id_ed25519_adhibera.pub
ssh-ed25519 AAAAC3Nza… info@adhibera.com

Geen sleutel?

Maak er dan eerst een. Dit hebben we in deze sessie niet gedaan, want de sleutel bestond al:

ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_adhibera -C info@adhibera.com

Kies bij de vraag om een passphrase een wachtwoordzin. Onze sleutel heeft er geen; zie het draaiboek, onder Nog te doen.

2. In de console:

  1. Ga in het project naar Security → SSH keys, en klik op Add SSH key.
  2. Plak de hele regel uit stap 1 in het grote veld.
  3. Vervang de naam door laptop-docent.
  4. Klik op Add SSH key.

3. Controle: Hetzner toont bij de sleutel een vingerafdruk. Vergelijk die met de vingerafdruk op de laptop:

ssh-keygen -l -E md5 -f ~/.ssh/id_ed25519_adhibera.pub
256 MD5:48:cf:49:37:62:28:7a:a8:b1:65:ef:8c:a6:1a:76:95 info@adhibera.com (ED25519)

Waar we tegenaan liepen

Bij het invullen viel er een stukje van het einde van de sleutel weg: er stond …zat7nfo@adhibera.com in plaats van …zat7 info@adhibera.com. Plak de sleutel daarom, typ hem niet over, en kijk het einde na. Het commentaar aan het eind (info@adhibera.com) mag ook weg; wij hebben de sleutel er de tweede keer zonder commentaar in gezet.

De naam is alleen een etiket in de console. Je kunt hem later wijzigen via Rename bij de sleutel.

6

browser2 min

De firewall maken

De firewall van Hetzner laat alleen SSH door (poort 22) en ping (ICMP). Er komt geen website op de server, dus meer hoeft er niet open.

  1. Ga in het project naar Firewalls en klik op Create Firewall.
  2. Inbound rules: er staan al twee regels, allebei van Any IPv4 en Any IPv6: TCP met poort 22, en ICMP. Laat die zo staan.
  3. Outbound rules: laat dit leeg. Dan mag de server alles naar buiten, en dat is nodig voor apt, git, uv en OpenAI.
  4. Apply to: laat dit leeg. Je koppelt de firewall straks bij het maken van de server.
  5. Name: vul alleen-ssh in.
  6. Klik op Create Firewall.

Waar we tegenaan liepen

Er kwam een venster What's New over de knop heen. Klik eerst op Got it.

Een korte naam: ssh klasserver

Met een blok in ~/.ssh/config hoef je het IP-adres en de sleutel niet steeds te typen. Eerst maak je een reservekopie van het bestand.

cp ~/.ssh/config ~/.ssh/config.bak-klasserver
cat >> ~/.ssh/config <<'EOF'

Host klasserver
  HostName <IP>
  User beheer
  IdentityFile ~/.ssh/id_ed25519_adhibera
  IdentitiesOnly yes
EOF
ssh root@klasserver 'echo "korte naam werkt: $(hostname)"'
korte naam werkt: klasserver
  • Bestaat ~/.ssh/config nog niet, sla de regel met cp dan over.
  • In het blok staat al User beheer, maar die gebruiker bestaat pas na stap 12. Tot dan schrijf je er root@ voor: ssh root@klasserver.
  • Later werkt ook ssh groep0@klasserver: dan log je met dezelfde sleutel in als de testgroep.

SSH dichtzetten

Nu mag er alleen nog met een sleutel ingelogd worden, en niet meer als root. Dat zet je in een eigen bestand. Bij sshd telt de eerste waarde die hij leest, en daarom begint de naam met 10-.

cat > /etc/ssh/sshd_config.d/10-klasserver.conf <<'EOF'
# Klasserver: alleen inloggen met een sleutel, niet als root
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
X11Forwarding no
EOF
sshd -t && systemctl restart ssh
echo "sshd herstart: $(systemctl is-active ssh)"
sshd -T | grep -Ei "^(passwordauthentication|kbdinteractiveauthentication|permitrootlogin|x11forwarding|pubkeyauthentication) "
sshd herstart: active
permitrootlogin no
pubkeyauthentication yes
passwordauthentication no
kbdinteractiveauthentication no
x11forwarding no
  • sshd -t test de instellingen eerst. Alleen als die kloppen, herstart systemctl restart ssh de SSH-server.
  • X11Forwarding no zet het doorsturen van grafische programma's uit. Dat gebruiken we niet.
  • Ubuntu 24.04 start SSH via ssh.socket. Omdat de poort niet verandert, is systemctl restart ssh genoeg.

Drie tests, in een nieuwe terminal op de laptop. Laat de tweede terminal met root nog open.

ssh klasserver 'echo "ingelogd als $(whoami), sudo: $(sudo -n whoami)"'
ssh -o BatchMode=yes root@klasserver true
ssh -o BatchMode=yes -o PubkeyAuthentication=no -o PreferredAuthentications=password,keyboard-interactive klasserver true
ingelogd als beheer, sudo: root
root@<IP>: Permission denied (publickey).
beheer@<IP>: Permission denied (publickey).
  1. beheer kan inloggen, en sudo werkt.
  2. root wordt geweigerd, ook met de juiste sleutel.
  3. Een wachtwoord wordt niet eens gevraagd: ssh biedt alleen nog publickey aan.

Slagen alle drie, sluit dan de terminal met root (exit). Vanaf nu log je in met ssh klasserver, en dat is beheer.

Zo deed Claude het

Claude testte met ssh -S none -o ControlMaster=no …, zodat de test niet stilletjes de open vangnetverbinding gebruikte. Met een gewone tweede terminal heb je dat niet nodig.

Het logboek

Wat een programma print, komt in het logboek van systemd (het journal). Dat logboek moet bewaard blijven na een herstart, en mag niet onbeperkt groeien. Bij ons bestond /var/log/journal al, maar er was geen maximum: dan mag het tot 4 GB groeien.

journald: active
[Journal]
[Journal]

SystemMaxUse=1G
[Journal]

Archived and active journals take up 17.8M in the file system.

Per groep zijn het zes commando's (zie stap 16). Bij tien groepen vergeet je er makkelijk een. Het script doet ze in één keer, en controleert eerst de sleutels. 1. Op de laptop: zet dit in een bestand nieuwe-groep.

#!/usr/bin/env bash
# Klasserver: maak een groep aan, met een gebruiker, sleutels, linger en grenzen.
# Gebruik: sudo nieuwe-groep groep3 sleutels-groep3.pub
set -euo pipefail

[[ $# -eq 2 ]] || { echo "Gebruik: sudo nieuwe-groep groepN sleutels.pub"; exit 1; }
[[ $EUID -eq 0 ]] || { echo "Start dit script met sudo."; exit 1; }
naam="$1"; sleutels="$2"
[[ "$naam" =~ ^groep[0-9]+$ ]] || { echo "De naam moet groepN zijn, bijvoorbeeld groep3."; exit 1; }
[[ -f "$sleutels" ]] || { echo "Het bestand $sleutels bestaat niet."; exit 1; }

# Controleer de sleutels voordat er iets verandert
if grep -q "PRIVATE KEY" "$sleutels"; then
  echo "Dit is een privésleutel. Die is nu niet meer geheim: laat de leerling een nieuwe maken."
  exit 1
fi
regels=$(grep -cvE '^[[:space:]]*(#|$)' "$sleutels" || true)
geldig=$(ssh-keygen -l -f "$sleutels" 2>/dev/null | wc -l || true)
[[ "$regels" -gt 0 && "$regels" -eq "$geldig" ]] || { echo "Van de $regels sleutels zijn er $geldig geldig."; exit 1; }
ssh-keygen -l -f "$sleutels"

adduser --disabled-password --gecos "" "$naam"
install -d -m 700 -o "$naam" -g "$naam" "/home/$naam/.ssh"
install -m 600 -o "$naam" -g "$naam" "$sleutels" "/home/$naam/.ssh/authorized_keys"
loginctl enable-linger "$naam"
systemctl set-property "user-$(id -u "$naam").slice" \
  MemoryMax=256M MemorySwapMax=0 TasksMax=128 CPUQuota=25%
echo "Klaar: $naam (UID $(id -u "$naam"))"
